Supply requirements

A capacity offer should describe what WDI can allocate, what the connections can run and how the supply will be charged. The details below let us assess the technical fit and agree an initial deployment.

Connections and countries
Provide the number of distinct residential public IPs, the country breakdown and the connection type. Explain whether addresses are shared between machines, how often they change and how the residential origin is established. Machine count and distinct IP count should be stated separately.
Runtime environment
Describe the operating system and architecture, CPU, memory, storage and whether containers are supported. Include the installation or management interface and any restrictions on long-running applications, outbound connections or client updates.
Bandwidth and continuity
State the available bandwidth, traffic allowance, usage limits and how resources are shared. Explain expected availability, maintenance windows and what happens if an address or allocation changes during the supply period.
Workload approval
Confirm who controls the connections and approves the intended public-web collection workload. WDI and the provider agree the supported client and operating limits before installation. The deployment and support section explains the division of responsibilities.
Price and allocation
Quote the capacity available for an initial allocation, the charging unit, currency and billing period. Include minimum commitments, included traffic, additional usage charges, payment terms and the notice required to change or end the allocation.
Delivery and support
Give a proposed start date, the expected delivery schedule and a technical contact. Describe the process for incidents, maintenance and replacement capacity, including which changes require advance approval.

WDI reviews the offer, checks the connection and workload fit, then agrees the initial allocation, duration, price and measurement plan with you. Expansion is discussed after the first deployment has been evaluated.

Network requirements

For a data-network deployment, describe the residential access and client environment your collection workload needs. WDI uses that specification to assess supply and define the operating scope.

Workload and integration
Identify the collection use case, supported node client and installation method. Include connection eligibility, network admission requirements and any resource or bandwidth expectations that affect the supply.
Countries and scale
Specify target countries, required connection types, distinct IP count and expected concurrency. Separate the initial allocation from the intended expansion, with timing for each.
Operating requirements
Describe the deployment duration, required availability, client-update process and incident contacts. Identify which party controls accounts, node configuration and changes to the workload.
Evaluation and terms
Agree the checks used to accept an allocation, the measurements used to review it, the proposed budget and payment basis. The supply agreement then records the scope, pricing and responsibilities before deployment begins.
